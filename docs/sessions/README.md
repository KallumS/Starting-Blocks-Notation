# Session logs

One file per working session, `YYYY-MM-DD-short-name.md`. What was asked, what
was built, what went wrong on the way, and what is still missing.

These are **not** a changelog - `git log` is the changelog, and it is better at
it. What a session log has that a commit message does not is the record of the
route: the bug that took four rendering passes to see, the test that passed
when it should not have, the thing that looked broken and was not. That is the
part nobody can reconstruct later, and the part that stops the next person
walking into the same wall.

Write one at the end of a session that changed something substantial. Include
the mistakes; a log that reads like everything went to plan is not worth the
disk space.
